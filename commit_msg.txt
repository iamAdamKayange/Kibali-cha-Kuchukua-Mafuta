Fix account switching regression and rate limiting issues

ROOT CAUSES IDENTIFIED:
1. useRequests hook had unstable dependency causing infinite loops
2. Header notification polling had role dependency causing duplicate intervals
3. API client refreshPromise not cleared on logout causing stale refresh loops
4. No user-specific cache invalidation on account switch

FIXES APPLIED:

1. useRequests Hook (src/hooks/useRequests.ts):
   - Removed 'filters' from useCallback dependency array
   - Added userId parameter to force refetch on account switch
   - useEffect now depends on userId to trigger fresh requests
   - Prevents stale data when switching accounts

2. Header Notification Polling (src/components/common/Header.tsx):
   - Changed dependency from [authUser?.id, authUser?.role] to [authUser?.id]
   - Prevents duplicate notification intervals on role changes
   - Ensures proper cleanup of polling intervals

3. API Client Token Management (src/lib/api.ts):
   - Enhanced clearToken() with logging
   - refreshPromise is now explicitly cleared on logout
   - Prevents stale token refresh loops after account switch
   - Added console.log for debugging session cleanup

4. Dashboard Components:
   - Added userId prop to RequestListPage component
   - Updated all dashboard pages to pass user?.id
   - Forces data refresh when user switches accounts
   - Covers: mkuu-idara, afisa-usafirishaji, ada-dahrm, ununuzi-ugavi, mwombaji

5. RoleDashboard (src/components/dashboard/RoleDashboard.tsx):
   - Added userId to useRequests call
   - Ensures fresh data fetch on account switch

6. Admin Reports (src/app/dashboard/admin/reports/page.tsx):
   - Added userId to useRequests call
   - Prevents admin data leakage to other roles
